**Patterns and Recurring Elements:**

*   **Helm Chart Structure**: Consistent use of `values.yaml` for default configurations and `values/<environment>.yaml` for environment-specific overrides across both `transaction-service` and `transaction-service-reconciliation-worker` charts.
*   **Datadog Integration**: Pervasive Datadog APM, monitoring, and SLO configurations, including annotations for services and containers, environment variables (`DD_SERVICE_MAPPING`, `DD_APM_COMPUTE_STATS_BY_SPAN_KIND`, `DD_APM_PEER_TAGS_AGGREGATION`), and detailed alerts often directed to `@slack-Tink-squad-transactions-oncall`.
*   **Vault Integration**: Both main service and worker deployments, as well as the reindex job, utilize Vault through `vaultify` init/sidecar containers for secure credential fetching and lease renewal, emphasizing a strong security posture.
*   **Kubernetes Deployment Practices**: Adherence to standard Kubernetes deployment patterns with `securityContext` for security hardening, liveness/readiness/startup probes for health checks, rolling updates for smooth deployments, and affinity rules for intelligent pod placement.
*   **Dynamic Image Tagging**: Container images are sourced from a specific ECR repository, with versions typically determined from a `tink-versions/tink-transaction-service.txt` file or defaulting to `latest`.
*   **Reconciliation Feature**: The `reconciliation` feature is often disabled and in `dryRun` mode in base `values.yaml` files, but frequently enabled and production-ready (`dryRun: false`) in environment-specific overrides for staging environments.
*   **Feature Toggles**: Configuration for a feature flagging system (Unleash) is consistently present through environment variables, indicating dynamic feature control.
*   **Resource and Scaling Management**: Standardized use of `podMemoryRequest`, `podCpuRequest`, `podMinReplicas`, `podMaxReplicas`, and `podTargetCPU` for managing resource allocation and Horizontal Pod Autoscaler (HPA) settings.
*   **Certificate Management**: Secure communication is ensured by mounting `grpc-certificate-aws` secrets and `ca-trust-bundle` configMaps across various components. The recent simplification in `reindex-job.yaml` suggests a move towards standardized CA bundle usage.
*   **GitHub Actions Workflow**: The introduction of `pull-request.yaml` indicates a strong emphasis on automated testing and consistent quality checks during the development lifecycle, utilizing `make` commands for local environment setup and test execution.
